# 調 v3「相棒」設計メモ

> 2026-10-07。目的: **メール処理を先生の代わりにほぼ済ませる相棒**にする。
> v2(夜間執事)は「判定して報告する」までだった。v3 は「判定 → 用意 → (聞く) → 送る → 片付ける → 見張る」まで回す。

## 1. v2 の実態と、相棒にならなかった理由

| 事実 | 影響 |
|------|------|
| v2 は一度も実行されていない(`nightly-digest.json` 無し、`butlerEnabled` 既定 false) | 設定を開いて有効化しないと何も起きない。相棒は「黙って働く」べき |
| `~/.claude/skills/shirabe` のシンボリックリンクが切れている | 連絡先・判断ルールを読まずに判定していた(無言で劣化) |
| 送信手段が `mailto:` しかない | 結局 eM Client を開いて自分で送る。ストレスの本体がそのまま |
| 受信箱を触れない(IMAP 未設定) | 不要メールが受信箱に残り続ける |
| 返事待ち・約束の追跡が無い | 「送ったきり」を人間が覚えておく必要がある |
| 画面が 13 ビュー | どこを見ればいいか分からない |

## 2. 相棒の仕事(ループ)

```
30分ごと(起動時・スリープ復帰時も)
  集める   新着(前回以降。初回だけ未読14日分)
  ふるう   迷惑 → 隔離 / 一斉配信 → 片付け候補
  片付ける 一斉配信を 既読 + アーカイブ(可逆・「戻す」あり)
  束ねる   スレッド単位の案件
  判断する 要件・期限・優先度・返信の種類・自動送信して安全か・先生に聞くべき問い
  用意する 返信下書き(先生の文体)。聞くべき問いがある案件は先に問いを出す
  任せる   権限が「任せる」なら定型返信(お礼・確認・了解・日程確定)を送信予定へ(猶予あり・取消可)
  見張る   先生が送って返事が無いスレッド → 催促案 / 返事が来たら自動で閉じる
  報告する 申し送り + 「今日」画面
```

## 3. 権限レベル(設定 → 相棒)

| モード | できること |
|--------|-----------|
| 見るだけ `observe` | 判定・申し送り・ノートのタグだけ。メールボックスに触らない |
| 任せる手前 `assist`(既定) | + 下書き、一斉配信の既読/アーカイブ、迷惑の隔離。送信は先生の「送る」1タップ(猶予付き・取消可) |
| 任せる `delegate` | + 常連/学内/面識ありへの定型返信(`autoSendSafe`)は自動で送信予定に載せる。決定が要るものは必ず聞く |

送信は常に **遅延送信(既定 5 分)+ 取消** を通す。不可逆な操作(ゴミ箱)は従来どおり承認制。

## 4. 画面「今日」

1. 相棒の一言(申し送り)+ 最終確認/次回 + 今すぐ確認
2. **決めてください** — 問い + 選択肢ボタン。答えると下書きが出て「送る」
3. **送るだけ** — 下書き済み。[送る] [直す] [後で] [しない]
4. **やること** — 返信以外の作業。[済み] [後で] [eM Client で開く]
5. **送信予定** — カウントダウン + [今すぐ] [取り消し]
6. **返事待ち** — N日。[催促する] [まだ待つ] [閉じる]
7. 折りたたみ: 参考 / 片付けた(戻す) / 相棒の日誌

## 5. 接続(設定 → 相棒 → アカウント)

- eM Client の `accounts.dat` から IMAP/SMTP のホスト・ポート・ユーザー名・表示名を自動検出(パスワードは取れない)
- 先生が入れるのはパスワードだけ。Gmail は OAuth なので **アプリパスワード**
- 署名は送信済みメールから自動推定(編集可)
- 接続テスト付き。未設定でも「送る」は eM Client の作成画面にフォールバック

## 6. 安全ライン

- 送信は遅延 + 取消。`delegate` でも初見の相手・決定が要る案件・P1 以外の期限案件は自動送信しない
- 片付けは「既読 + アーカイブ」のみ(削除しない)。グループ単位で「戻す」
- 全操作を日誌(`journal/YYYY-MM-DD.jsonl`)に残す
- AI は Claude Code CLI 経由(API キー不要)。ツール無し・MCP 無しの軽量呼び出し

## 8. v3.1 追加(2026-10-07 夜): 作業への受け渡し・カレンダー

- **作業指示書**(`partner:handoffPrepare`): 案件 + スレッド + `references/folder-map.md` から該当フォルダを推定し、目的・経緯・やること・期限・成果物・返信方針の Markdown を `userData/handoff/<case>.md` に書く。AI はフォルダを創作せず、確信が無ければ年度/カテゴリまでにとどめる。先生が [変更] で選んだフォルダは AI で上書きしない
- **出口**(`partner:handoffOpen`): `terminal` = Terminal.app で `cd <folder> && claude "<指示書を読んで…>"`。`finderai` = `open -a FinderAI <folder>` + tmux セッション `finderai-claude-<sha256(realpath)先頭6バイト>`(FinderAI と同じ命名)へ `send-keys`、無ければ先に `new-session -d` で用意(FinderAI は `-A` で同名に繋ぐ)。`folder` = Finder で表示
- **eM Client の下書きへ**(`partner:draftToEmClient`): 署名・引用・In-Reply-To 付きの RFC822 を IMAP APPEND で下書きフォルダへ。IMAP 未設定なら mailto
- **カレンダー**: 判定で `event`(title/start/end/allDay/kind)を抽出 → 全アカウントの eM Client カレンダー(120日先まで)と照合。同時刻(15分以内)で共通語あり、または ±90 分で件名類似なら登録済み。未登録は「今日」で朱の警告、[カレンダーに登録] は ICS を `open -a "eM Client"`(DB には書かない)。登録されれば次回の確認で消える
